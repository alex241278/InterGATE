# InterGATE source and provenance

This source archive contains the InterGATE implementation, notebooks with their outputs cleared, preprocessing and analysis code, configuration files, benchmark protocols and provenance manifests. It includes the authors' derived 288-gene panel required by the frozen XGBoost protocol and the 50-symbol PAM50 exclusion list used in signature analyses. The accompanying SHA-256 checksum identifies the exact archive. The source for the original study was verified by anonymous access on 23 November 2026 at Git commit `e9ca9a7ac563758278557a6bbfaa11cc78cb54a1`. The revision adds the code for the additional experiments, the corrected supplementary network visualisations and the supplementary workbook, together with updated installation constraints and expanded manifests. The study data, rendered figures and supplementary workbooks are obtained separately. [Original public source](https://github.com/alex241278/InterGATE/tree/e9ca9a7ac563758278557a6bbfaa11cc78cb54a1)

## Execution

Unpack the archive into an empty directory. Use its sibling directories `InterGATE/` and `revision_CMPB/` for the study and revision analyses, respectively. Run the preprocessing notebooks listed in `InterGATE/data_prepare/ORDEN_EJECUCION.md`. The training and evaluation order and inputs are described in `InterGATE/RUN_FROM_SCRATCH.md` and the notebook names. Retrieve the individual, release-specific public inputs listed in `manifests/resources.csv` under the corresponding data providers' access terms. The manifests give the checksums for verifying files and identify when an upstream release or archived download URL could not be established. Compare the regenerated prepared files, ordered cohort counts, candidate prior and train/validation split with the recorded checksums. The supplied InterGATE SHA-256 implementation fingerprint is the one recorded at the original training run. The inventory inside the archive records each distributed file after packaging.

The historical execution of notebook 00 records Python 3.11.9 with ten numerical and application libraries; see `manifests/training_environment.json`. The local revision requirements and project metadata correct the historical working copy’s upper bound and permit PyTorch 2.7.1, the version actually logged. The public baseline uses its own broader range, `torch>=2.3,<3`, which already includes that version. Install the historical PyTorch build from its CUDA 11.8 channel and use `manifests/training_constraints.txt` to pin the recorded libraries when installing the remaining dependencies. For example, on a compatible Linux host with Python 3.11.9, run from inside the unpacked InterGATE directory:

```bash
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu118
python -m pip install -r requirements.txt -c ../manifests/training_constraints.txt
python -m pip install -e . --no-deps
```

Package-specific availability and platform wheels matter. The archive does not establish a historical freeze of all transitive dependencies. The kernel metadata from the preparation and analysis notebooks identify additional Python 3.14.6 environments. Those kernel records reflect notebook metadata; packages from those environments must not be inferred from the training snapshot. The constraints above apply to model training. For GeSubNet install the separate revision-analysis dependencies described in its protocol and run guide. A fresh end-to-end installation and a full rerun of the original seven-cohort pipeline have not been certified from the archive alone.

### Supplementary figures, nested external analysis and workbook export

Obtain `Supplementary_Data_1_Basal_like_strict_core.xlsx` from the article's supplementary materials. Its SHA-256 is `2c7bbe6afcd8190be2c829aae3fa01e174feb2d6c5d4916caf9f92c3c58e7eba`. From the archive root, place it under `2027_InterGATE/Supplementary Data/` with that filename. This location works for both `revision_CMPB/analysis/figures/redraw.py`, which uses the archived gene inventory to verify figure annotations, and `revision_CMPB/analysis/r2_cohorts/nested_external.py`, which checks the archived pair estimates and the original multiple-testing correction. The latter script first checks `revision_CMPB/manuscript/Supplementary Data/` for a copy of the same workbook. Use identical copies if both locations are populated.

The scientific analysis scripts write their numerical results to CSV files. The optional `revision_CMPB/analysis/build_supplementary_data.mjs` exporter assembles the completed tables into the formatted Supplementary Data 5 workbook. This export uses Node.js, the `@oai/artifact-tool` spreadsheet library and a Python environment containing NumPy, pandas and openpyxl. Set `CODEX_WORKSPACE_DEPENDENCIES` to a compatible runtime directory containing `node/node_modules/@oai/artifact-tool` and `python/bin/python3`. From the archive root, create `revision_CMPB/manuscript/Supplementary Data/` and run `node revision_CMPB/analysis/build_supplementary_data.mjs` after generating the source CSVs. The workbook exporter calls the nested external analysis before assembling the worksheets. The scientific calculations and CSV outputs can be reproduced independently of this spreadsheet runtime.

## Public baseline and revision audit

All 38 `intergate/` Python modules from the pre-revision working copy initially matched the immutable public commit byte for byte, as did the central configuration and the two XGBoost protocol files. The public repository also provides preprocessing and analysis notebooks, contract and synthetic tests, a public DepMap 26Q1 manifest, execution documentation and kappa-sensitivity tables. Original data and new revision results are distributed independently. The content inventory identifies the public Git blob and SHA-256, and the matching or differing source in the local archive. Public and local packaging metadata differ. Notebook serialization, cleared outputs and the deliberate sanitization of a contact address also affect file-level checksums.

Three published CI checks passed on the unchanged public snapshot. A fourth standalone regression test detected a discrepancy in how the upstream XGBoost panel-contrast helper handled tied null counts. Its floating-point subtraction excluded the three tied draws in the focal example. The revision package compares integer count differences and uses an integer-scaled centered statistic for the two-sided tail. The unchanged upstream regression test now passes. Regenerating all four signature contrasts with the corrected module reproduces the submitted Supplementary Data 3, including the Basal-like one-sided P = 14/1001, four-signature FDR = 0.055944, two-sided P = 22/1001 and two-sided FDR = 0.087912. An older intermediate local CSV contains the preliminary values. The reported manuscript result requires no change. The archive includes the synthetic and panel-contrast regression tests under `InterGATE/tests/`. The two repository-layout checks apply to the linked snapshot. [Public tests](https://github.com/alex241278/InterGATE/tree/e9ca9a7ac563758278557a6bbfaa11cc78cb54a1/tests)

## Resource identity

The authors' retained HuRI TSV and PSI data, HuRI mapping-dependent cache and the signed directed OmniPath API export are identified by exact byte length and SHA-256 in the inventory. The original code records the upstream URLs and request parameters. No authoritative release number or download timestamp is embedded in these snapshots. Those historical facts cannot be inferred from local file timestamps. For MSigDB the two GMT files correspond to release 2026.1.Hs. The cohort manifest enumerates the seven sources and their roles. It also identifies and hashes the development train/validation membership by position in the frozen expression-column order.

The original supplementary methods and the immutable public repository’s DepMap manifest identify DepMap Public 26Q1, and the three retained files match all three SHA-256 checksums recorded by the study. Chronos is the upstream generator of the released gene-effect matrix. The authors used that matrix directly. Broad's 26Q1 release notes describe its screen-library correction. The local manifests contain no Chronos implementation commit or executable version. The public catalogue returned an interactive verification page during this check; the historical release assignment is supported by the submission and the internal file hashes rather than an independent match to Broad's checksum catalogue. Later releases may have different gene-effect values.
